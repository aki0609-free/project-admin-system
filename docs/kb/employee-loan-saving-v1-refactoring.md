# 従業員貸付・積立 V1 基盤

## 1. 目的

従業員の貸付残高と積立残高を、日報に登録した実際の受領額と整合させる。

V1では承認ワークフローを導入せず、登録データは承認済みとして扱う。

## 2. 業務ルール

### 2.1 貸付

- 1人の従業員に対して、有効な貸付は1件だけ登録できる。
- 新規登録時の貸付残高は、借入元本と同額で開始する。
- 月返済額は返済予定額であり、日報へ自動計上しない。
- 日報の返済額には、その日に実際に返済された金額を入力する。
- 日報保存時点で貸付残高を減額する。月次締めを待たない。
- 一括返済にも対応し、残高が0円になると貸付を完済扱いにする。
- 貸付残高を超える返済は登録できない。
- 返済開始後は借入元本を変更できない。
- 一部返済済みで残高のある貸付は削除できない。有効解除で管理する。

### 2.2 積立

- 1人の従業員に対して、有効な積立設定は1件だけ登録できる。
- 新規登録時の積立残高は0円で開始する。
- 積立率は0%以上100%以下とする。
- 月積立予定額は参考値であり、日報へ自動計上しない。
- 日報の積立額には、その日に実際に受領した金額を入力する。
- 日報保存時点で積立残高を増額する。
- 積立残高がある設定は削除できない。有効解除で管理する。

### 2.3 日報の修正・削除

- 日報の積立額または返済額を修正した場合は、変更差額だけを残高へ反映する。
- 日報を削除した場合は、その日報で反映した積立・返済を取り消す。
- 差し戻しによって積立残高がマイナスになる操作は拒否する。
- 返済取消後の貸付残高が借入元本を超える操作は拒否する。

## 3. 画面仕様

- 貸付残高・積立残高は参照専用とし、画面から直接変更しない。
- 貸付登録後の従業員は変更できない。
- 積立登録後の従業員は変更できない。
- 承認状態はV1画面に表示せず、バックエンドで `APPROVED` に固定する。
- 入力エラーは `EMPLOYEE_FINANCE_INVALID_REQUEST` と業務メッセージを返す。

## 4. 積立予定額

現在の参考値は次の式で算出している。

```text
最低給与額 × 積立率 ÷ 100
```

実際の月次給与額を基準にした積立計算は、給与計算・月次締め側で確定する。
日報作成時には自動控除しない。

## 5. DB資産

適用対象：

```text
backend/src/main/resources/sql/employee/finance_foundation_v1.sql
```

実施内容：

- 有効な貸付・積立データをV1の承認済み状態へ統一
- 有効データ検索用インデックスを追加
- 既存データは削除しない

AWS反映時は次の一括スクリプトに含まれる。

```text
infrastructure/scripts/database/apply_runtime_schema_upgrade.sh
```

## 6. 動作確認項目

1. 貸付10万円を登録すると残高10万円になる。
2. 日報で10万円を返済すると、保存直後に残高0円になる。
3. 残高を超える返済は拒否される。
4. 日報の返済額を減らすと、差額分の残高が戻る。
5. 日報を削除すると、その日報の返済・積立が取り消される。
6. 同一従業員へ有効な貸付を2件登録できない。
7. 同一従業員へ有効な積立設定を2件登録できない。
8. 残高は編集画面から直接変更できない。

## 7. V2候補

- 承認ワークフロー
- 貸付・積立の入出金明細台帳
- 残高調整専用画面と調整理由の監査記録
- 給与計算結果を基準とした積立額の自動確定
- 複数貸付を許可する場合の返済充当順序
