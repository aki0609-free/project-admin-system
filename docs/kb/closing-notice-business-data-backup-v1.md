# 締日通知・業務データZIPバックアップ V1

## 1. 目的

既存のお知らせ管理基盤とデータバックアップ基盤を利用し、次を追加する。

- 顧客ごとの締日当日通知
- 自社給与締日当日通知
- 顧客・顧客取引・従業員・日報のZIPダウンロード

新しい個別画面や専用処理は作らず、既存の管理画面と共通基盤へ設定を追加する。

## 2. 影響範囲

| 領域 | 変更内容 |
|---|---|
| NoticeRule | 締日通知ルール2件を追加 |
| ダッシュボード | 自動生成された締日通知を既存のお知らせとして表示 |
| バックアップ対象管理 | 業務データ4対象を追加 |
| バックアップ実行 | 既存の複数選択・ZIP生成・ダウンロードを利用 |
| DB共通資産 | AWS・ローカル・Testcontainersで同じSQLを適用 |

## 3. 締日通知

### 3.1 顧客締日

| 項目 | 値 |
|---|---|
| Ruleコード | `CUSTOMER_CLOSING_DAY` |
| 参照元 | `customers` |
| 日付ルール | `closing_day_type`＋`closing_day_value` |
| 表示名 | `customers.name` |
| 通知日 | 締日当日 |
| 重要度 | IMPORTANT |

通知本文は顧客締め処理と請求内容の確認を促す。

### 3.2 自社給与締日

| 項目 | 値 |
|---|---|
| Ruleコード | `COMPANY_PAYROLL_CLOSING_DAY` |
| 参照元 | `closing_setting` |
| 対象設定 | `setting_code = 'PAYROLL'` |
| 日付ルール | `closing_day_type`＋`closing_day_value` |
| 通知日 | 締日当日 |
| 重要度 | IMPORTANT |

通知本文は月次締め処理と給与帳票の確認を促す。

### 3.3 実行・重複防止

- 1時間ごとに締日を判定する。
- アプリが業務開始後に起動した場合も、次の正時に判定できる。
- `notice_generated`の一意制約により、同じRule・対象・締日では1回だけ生成する。
- 通知時刻や事前通知へ変更する場合は、お知らせ管理のNoticeRule設定を変更する。

## 4. 業務データバックアップ

### 4.1 初期対象

| 対象コード | CSV | 元テーブル |
|---|---|---|
| `BACKUP_CUSTOMERS` | `customers_*.csv` | `customers` |
| `BACKUP_CUSTOMER_TRANSACTIONS` | `customer_transactions_*.csv` | `customer_transactions` |
| `BACKUP_EMPLOYEES` | `employees_*.csv` | `employee` |
| `BACKUP_DAILY_REPORTS` | `daily_reports_*.csv` | `daily_report` |

### 4.2 出力仕様

- SYS_ADMINだけが実行できる。
- 出力モードは`DOWNLOAD`とする。
- CSVはUTF-8・ヘッダー付きとする。
- 4対象を選択すると1つのZIPとしてダウンロードする。
- 各対象は`zip_required = true`のため、1対象だけでもZIPになる。
- テナントIDで絞り込み、他テナントのデータを含めない。
- S3やサーバーへは保存せず、既存のバックアップ履歴だけを記録する。

### 4.3 カラム追従

バックアップ列は`information_schema.columns`から現在の全カラムを同期する。
対象テーブルへカラムを追加した場合、共通DB資産を再適用すればバックアップ対象へ追加される。

### 4.4 V1の対象外

今回のZIPは依頼された4つの本体テーブルを対象とする。次の関連テーブルは含めない。

- 顧客現場・顧客単価などの顧客関連子テーブル
- 従業員契約・税設定・貸付・貯金などの従業員関連子テーブル
- 日報の可変手当・可変控除などの日報関連子テーブル

復元用途まで含む完全バックアップが必要になった場合は、関連テーブルを追加し、
外部キー依存順を定義した別のバックアップセットとして拡張する。

## 5. テスト

- 空のMySQLへ全共通DB資産を適用できる。
- 締日当日に顧客・自社の通知が各1件生成される。
- 同じ日に再実行しても通知が重複しない。
- 指定4テーブルの全カラムがバックアップ定義へ登録される。
- 実行結果がZIPであり、4つのCSVエントリを含む。
