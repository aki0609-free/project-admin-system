# 従業員入寮情報・寮費控除 V1設計

## 1. 目的

従業員の入寮状態と寮タイプを管理し、日報の動的控除Ruleから日次寮費を計算できるようにする。

## 2. 従業員項目

| 画面項目 | DBカラム | 値 |
| --- | --- | --- |
| 入寮あり | `employee.dormitory_flag` | `true` / `false` |
| 寮タイプ | `employee.dormitory_type` | `SINGLE_ROOM` / `SHARED_ROOM` |

- 入寮なしの場合、寮タイプは未設定にする。
- 入寮ありの場合、寮タイプは必須とする。
- 既存従業員は入寮なしとして移行する。

## 3. 寮費を従業員マスターへ持たせない理由

寮費は業務ルールであり、将来の金額変更、会社別設定、寮タイプ追加に対応する必要がある。

従業員マスターには判定材料だけを保持し、金額は次の既存基盤で管理する。

```text
控除マスター → AUTO計算 → Rule → 日報控除明細
```

## 4. Rule標準パラメータ

日報の手当・控除Ruleへ次の値を渡す。

| パラメータ | 型 | 内容 |
| --- | --- | --- |
| `employeeId` | LONG | 従業員ID |
| `dormitoryFlag` | BOOLEAN | 入寮中か |
| `dormitoryType` | STRING | `SINGLE_ROOM` または `SHARED_ROOM` |
| `targetDate` | DATE | 日報対象日 |
| `dormitoryDailyAmount` | DECIMAL | 業務設定の寮タイプ別日額 |
| `dormitoryChargeDays` | INTEGER | 当該日報で徴収する日数（0〜31） |

## 5. 寮費Ruleの推奨形

```text
入寮なし                         → 0円
入寮あり                         → 寮費日額 × 寮費徴収日数
```

V1のRule名は `DORMITORY_DAILY_FEE` とし、JEXL式は次のとおりとする。

```text
dormitoryFlag ? dormitoryDailyAmount * dormitoryChargeDays : 0
```

日額は「管理者メニュー → 業務設定 → 寮費設定」で管理する。初期値は誤徴収防止のため0円とする。

## 6. 日報を作成しない日の扱い

日報に `寮費徴収日数` を保持する。

- 入寮中の従業員を新規選択した場合の初期値：1日
- 入寮していない従業員：0日
- 土日など日報を作成しない日：前後の任意の日報へまとめて入力可能
- 例：金・土・日の3日分をまとめる場合は3日

どの営業日へ休日分を載せるかは固定しない。運用変更に対応できるよう、日数だけを保存する。

## 7. 日次・月次の処理

1. 日報入力時に寮費Ruleを実行する。
2. 計算結果を日報控除明細へ保存する。
3. 日報修正時は寮費も再計算する。
4. 月次帳票は確定済み日報の寮費控除を合計して表示する。

月次で寮費を再計算しない。日次に保存された確定値を集計するため、途中で寮費Ruleの金額を変更しても過去日報の金額は勝手に変化しない。

## 8. Rule基盤の柔軟性

Rule呼出しは `Map<String, Object>` でパラメータを受け取り、Ruleマスター側で次を設定できる。

- パラメータ名
- データ型
- 必須／任意
- 初期値
- JEXL／MVEL／Java Beanの実装方式

そのため、日額や計算式の変更は原則としてアプリケーションの再ビルドなしで行える。一方、新しい業務事実を画面入力・DB保存する場合は、DTO・Entity・標準コンテキストへの追加が1回必要になる。任意のテーブルやカラムを無制限に参照させないのは、SQLインジェクションと情報漏えいを防ぐための意図した制限である。
