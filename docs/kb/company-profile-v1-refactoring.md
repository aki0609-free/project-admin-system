# 会社情報 V1安定化

## 1. 対象

```text
右上のユーザーメニュー
  └ 会社情報
```

会社情報は、画面表示だけでなく次の帳票・台帳から参照される基幹マスターである。

- 月次請求書
- 月次給与明細
- 日次作業伝票
- 月間労務表
- 労務費支払一覧
- 入金確認表

## 2. V1仕様

会社情報はテナントごとに1件の有効レコードを使用する。

```text
tenant_id = ログインユーザーのテナント
active_flag = true
deleted_at IS NULL
ID昇順の先頭1件
```

会社コードを編集して保存しても、別会社を追加せず現在の会社情報を更新する。

会社情報を無効化すると帳票生成が成立しないため、V1の会社情報画面では有効・無効を変更させず、保存時に常に有効とする。API互換性のため`activeFlag`項目自体は維持する。

## 3. 権限

| 操作 | SYS_ADMIN | その他のログインユーザー |
|---|---:|---:|
| 閲覧 | 可 | 可 |
| 編集・保存 | 可 | 不可 |

バックエンドのPUT APIでも`SYS_ADMIN`を再検証する。画面のボタン非表示だけには依存しない。

## 4. API

| Method | Path | 用途 |
|---|---|---|
| GET | `/api/system/company-profile` | 現在有効な会社情報を取得 |
| PUT | `/api/system/company-profile` | 現在の会社情報を登録または更新 |

DBカラムとAPI形式は変更しない。

## 5. 保存処理

```text
TenantContextからtenantIdを取得
  ↓
同一tenantの有効な会社情報を取得
  ↓ 見つからない場合
同一tenant・同一companyCodeの既存情報を取得
  ↓ 見つからない場合
新規作成
  ↓
入力検証・正規化
  ↓
tenantIdを明示設定、activeFlag=trueを強制
  ↓
保存
```

Repositoryの会社情報検索には`tenantId`を引数として明示する。Hibernate Filterも維持するが、テナント分離を暗黙処理だけへ依存させない。

## 6. 入力検証

- 会社コード：必須、100文字以内
- 会社名：必須、255文字以内
- 資本金：画面では文字列として入力し、半角数字・小数2桁・カンマ区切りを許可する。保存時にカンマを除去して0以上の数値へ変換する
- メールアドレス：メール形式
- Webサイト：`http://`または`https://`
- 適格請求書発行事業者登録番号：`T`と13桁の数字
- その他の文字項目：DBカラム長以内

フロントエンドとバックエンドの両方で検証する。フロントエンド検証は操作性のため、バックエンド検証はAPI直接呼出し時の整合性保証のために行う。

## 7. 画面

### 閲覧

次の3タブで確認する。

- 会社情報
- 請求書設定
- 許認可・事業内容

会社情報タブでは会社コード、商号、カナ・略称、代表者、所在地、電話、FAX、メール、Webサイト、対応エリア、資本金を表示する。

許認可・事業内容タブでは、代表許可番号を含めて表示する。

### 編集

共通`AppDialog`、`TabLayout`、`FormLayout`、`GridBasedForm`を使用する。

取得・保存失敗はダイアログ内のエラー表示で通知する。保存中は二重送信とダイアログ終了を抑止する。保存成功通知は4秒、エラー通知は8秒で自動的に閉じ、手動でも閉じられる。

## 8. 変更しない範囲

- `company_profile`テーブル構造
- 帳票・台帳側の会社情報取得項目
- APIのURLとリクエスト・レスポンス形式
- SYS_ADMINだけが編集できる権限仕様

## 9. テスト

バックエンド：

- 会社コード変更時も現在レコードのIDが維持される
- リクエストが無効指定でも会社情報は有効のまま保存される
- Repository検索へ現在のtenantIdが明示される
- 不正な適格請求書発行事業者登録番号を拒否する

フロントエンド：

- 正常な会社情報を検証できる
- 不正なメール、Webサイト、登録番号を拒否する
- 会社情報ダイアログと3タブを操作できる
- 有効・無効の入力欄が表示されない
- 不正な登録番号の保存前エラーが表示される
