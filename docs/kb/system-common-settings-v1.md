# システム共通設定 V1

## 1. 目的

業務固有の設定と、複数機能から参照されるシステム共通設定を分離する。
管理画面は「システム運用 → 共通設定」に置き、業務管理から独立させる。

## 2. 設計

共通設定は、設定項目そのものを表す `system_setting_definition` と、
テナントごとの入力値を表す `system_setting_value` に分離する。

定義は次の3階層の安定キーで識別する。日本語表示名はキーと分離し、名称変更で参照処理が壊れないようにする。

- 大分類キー
- 中分類キー
- 小分類キー

定義には表示名、説明、値型、必須フラグ、検証パターン、プレースホルダー、表示順を持たせる。
管理画面は定義を取得して、値型（文字列・数値・真偽値・URL・日付・JSON）に応じた入力欄を動的に表示する。

設定項目には次のスコープを持たせる。

- `SYSTEM`: 全社共通の標準項目。定義は保護し、テナントごとの設定値だけ変更を許可する。
- `TENANT`: 会社独自項目。登録した会社の管理者だけが追加・編集・論理削除できる。

分類キーは業務処理から参照する安定識別子であるため、登録後は変更できない。
値型を変更する場合は、登録済みの値が変更後の型・必須条件・入力規則を満たす場合だけ許可する。

管理APIは次の通り。

- `GET /api/system/common-settings`
- `PUT /api/system/common-settings/values`
- `GET /api/system/common-settings/definitions`
- `POST /api/system/common-settings/definitions`
- `PUT /api/system/common-settings/definitions/{id}`
- `DELETE /api/system/common-settings/definitions/{id}`

管理画面は「設定値マスター」に統合し、定義と現在値を共通テーブルの1行として表示する。
上部ツールバーでは大分類・中分類・小分類を段階的に絞り込み、テーブル標準の列検索も併用できる。
行クリックで編集画面を開き、標準項目は設定値だけ、会社独自項目は定義と設定値を編集する。
会社独自項目の追加・更新は定義と設定値を同一トランザクションで保存する。
削除は定義と当該会社の値を論理削除し、標準項目には削除操作を表示しない。

## 3. サポートリンク

ヘッダーのユーザーメニューで利用する次のURLをテナント単位で管理する。

- マニュアルURL
- インシデント報告URL

サポートリンクは共通設定の一分類として、次のキーで登録する。

- `SYSTEM / SUPPORT_LINK / MANUAL_URL`
- `SYSTEM / SUPPORT_LINK / INCIDENT_REPORT_URL`

通常利用者向けの参照APIは `/api/support-links` とする。登録可能なURLはHTTPSだけに限定する。

旧フロントエンドのキャッシュ互換のため、旧管理API
`/api/admin/business-settings/external-support-links` は移行期間中だけシステム共通設定へ転送する。
新しい画面・コードから旧管理APIを利用してはならない。

既存の `external_support_link_setting` の値は導入SQLで `system_setting_value` へ移行し、
移行後に専用テーブルを削除する。未登録時は空値を返し、ヘッダー側は環境変数で定義された既定URLへフォールバックする。

## 4. 境界

単一値として扱えない業務データは「設定値マスター」へ直接置かない。複数行・複数項目を持つ業務マスターは、同じ共通設定画面の「汎用マスター定義」で入力構造を定義し、公開後に業務管理の動的タブからデータを登録する。年末調整などの取引処理は引き続き専用業務機能で扱う。

汎用マスター基盤の契約は`generic-master-foundation-v1.md`を正規仕様とする。
今後追加する場合も、複数の業務機能から共通参照される設定だけを対象とする。
