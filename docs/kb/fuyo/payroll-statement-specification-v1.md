# Fuyo 日次・月次給与明細仕様 V1

## 1. 目的

Fuyoにおける日次給与明細と月次給与明細の支給、手当、控除、残高および月次精算方法を定義する。

本仕様では、計算式を変更可能にするRule基盤と、履歴・残高・再締めの整合性を保証する取引／帳票基盤の責務を分離する。

日報保存時はRuleで給与・手当・控除を計算する。月次締め時はJavaで同じ項目を再計算せず、日報確定値、月次取引、税・保険マスターをViewで集計し、ストアドでhistoryへ確定する。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 日次給与 | 月給者へ日次で実際に支払う金額。月次では月給の前払いとして精算する |
| 前払い | 給与締め期間内に支払済みとなった日次給与の合計 |
| 前借り | 従業員貸付基盤で管理する会社から従業員への貸付 |
| 法定預り額 | 日次給与支払時に手入力で一時的に預かる金額。税額の自動計算結果ではない |
| 法定預り返金額 | 月次締め時に未返金の法定預り額残高を全額返金する金額 |
| 貯金額 | 日報で入力し、会社預り貯金へ加算する金額 |
| 借入金返済額 | 日報で入力し、従業員貸付残高から減算する金額 |

## 3. 日次給与計算

### 3.1 勤怠から計算する固定項目

次の項目は手当マスターへ登録しない。日報の勤怠、従業員契約および日報給与Ruleから計算し、日報の専用カラムへ保存する。

| 表示項目 | 保存項目 | 計算元 |
|---|---|---|
| 基本給相当 | `normal_pay_amount` | 給与契約、通常勤務時間、Rule |
| 早出残業手当 | `overtime_pay_amount` | 給与計算用時間単価、早出残業時間、Rule |
| 深夜手当 | `night_pay_amount` | 給与計算用時間単価、深夜時間、Rule |
| 休日手当 | `holiday_pay_amount` | 給与計算用時間単価、休日時間、Rule |

Fuyoでは全従業員を月給者として扱う。日報給与計算では4種類の有効な給与Ruleを必須とし、1件でも不足または無効の場合は設定エラーとして日報計算を中止する。未設定を0円やJavaの代替計算として確定しない。

Ruleの初期方針：

```text
基本給相当
  = 月給から算出した給与計算用時間単価 × 通常勤務時間

早出残業手当
  = 給与計算用時間単価 × 早出残業時間 × 適用割増率

深夜手当
  = 給与計算用時間単価 × 深夜時間 × 適用割増率

休日手当
  = 給与計算用時間単価 × 休日時間 × 適用割増率
```

割増率はサービスクラスへ直書きせず、Ruleまたは期間付きマスターで管理する。

### 3.2 日次手当

| コード | 表示名 | 日次表示 | 月次表示 |
|---|---|---:|---:|
| `ATTENDANCE_ATTITUDE` | 勤務態度手当 | あり | あり |
| `DRIVER_ALLOWANCE` | 運転手当 | あり | あり |
| `MANAGEMENT_ALLOWANCE` | 管理手当 | あり | あり |
| `OTHER_ALLOWANCE` | その他手当 | あり | 必要に応じてあり |

これらは手当マスターと日報の可変手当基盤を使用する。勤務態度手当はRule計算を使用せず、日報で0円以上の金額を手入力して保存する。月次給与明細では、締め期間内に保存された勤務態度手当を合計する。それ以外のRule計算項目は日報保存時に確定し、過去日報をRule変更だけで自動変更しない。

## 4. 日次給与明細

### 4.1 支給

- 基本給相当
- 早出残業手当
- 深夜手当
- 勤務態度手当
- 運転手当
- 管理手当
- その他手当
- 当日支給額

「前払い」という名称は日次給与明細へ表示しない。当日支給額は月次締めで前払いとして集計する。

### 4.2 控除1

#### 法定預り額

- 日報で手入力可能とする。
- 固定額マスターや税額計算Ruleから自動決定しない。
- 所得税、社会保険、住民税などを日次では差し引かない。
- 入力額は日報保存時点の確定値として履歴へ残す。
- 日報修正・削除時は差額を残高へ反映する。

#### 法定預り額残高

```text
法定預り額残高
  = 過去の日次法定預り額累計
  - 過去の有効な法定預り返金額累計
```

残高は計算Ruleの戻り値だけで管理せず、入出金取引履歴から算出する。

### 4.3 控除2・残高

| 項目 | 取得／更新元 |
|---|---|
| 前借り額 | 従業員貸付基盤の借入元本 |
| 前借り残高／借入金残高 | 有効な従業員貸付の`current_balance` |
| 借入金返済額 | 日報で入力し、貸付残高から減算 |
| 貯金額 | 日報で入力し、貯金残高へ加算 |
| 貯金残高 | 従業員貯金基盤の`current_balance` |
| 寮費 | 日報の確定控除額 |
| 寮費支払日数 | 日報の徴収日数 |
| 寮費残日数 | 汎用控除残高基盤 |
| 携帯電話貸出料 | 日報控除または確定済み控除取引 |
| 携帯電話貸出料残高 | 汎用控除残高／取引基盤 |
| Wi-Fi使用料 | 日報控除または確定済み控除取引 |

「借入金返済貯金」という項目は使用しない。`借入金返済額`と`貯金額`へ分離する。

## 5. 月次給与明細

### 5.1 支給

- 基本給
- 早出残業手当
- 深夜手当
- 勤務態度手当
- 運転手当
- 管理手当
- 可変手当

### 5.2 控除1

- 健康保険
- 子ども・子育て支援金
- 厚生年金
- 雇用保険
- 所得税
- 住民税
- 社会保険計
- 課税対象額

社会保険計と課税対象額は表示用マスター項目ではなく、税・保険Viewの計算結果として扱う。

### 5.3 控除2・精算

| 項目 | 計算方法 |
|---|---|
| 前払い | 会社給与締め期間内の`daily_payments.status = PAID`の`actual_amount`合計 |
| 寮費 | 期間内の日報確定寮費＋月次徴収方式の確定控除取引 |
| 携帯電話貸出料 | 期間内の確定済み日報控除または控除取引 |
| Wi-Fi使用料 | 期間内の確定済み日報控除または控除取引 |
| 貯金額 | 期間内の日報`saving_amount`合計 |
| 貯金残高 | 月次締め時点の従業員貯金残高 |
| 借入金返済額 | 期間内の日報`loan_repayment_amount`合計 |
| 借入金残高 | 月次締め時点の従業員貸付残高 |
| 法定預り返金額 | 締め対象期間終了時点の未返金法定預り残高全額 |

前払いの対象期間は会社側の給与締日を使用し、顧客締日は使用しない。

## 6. 法定預り返金

### 6.1 月次処理

月次締め時に、締め対象期間終了日までの未返金法定預り残高を全額返金する。

```text
締め対象期間終了時点の法定預り残高
  -> 月次給与明細の法定預り返金額
  -> 返金取引を登録
  -> 対象残高を0円
```

現在残高を直接0円へ更新するだけの実装は禁止する。返金取引を保存し、預りと返金の履歴から残高を再現できるようにする。

### 6.2 再締め

- 旧Versionの給与明細historyは保持する。
- 旧Versionの返金取引を二重計上しない。
- 再締めでは直前の有効な締め返金を置換または取消扱いにして、最新の日報から返金額を再計算する。
- 最新Versionの返金取引だけを現在残高へ反映する。
- 締め期間終了後に入力された次期間の預り額を、過去月の再締めで消さない。

## 7. Rule基盤の責務

### 7.1 Ruleで行うもの

- 基本給相当の計算
- 早出残業、深夜、休日手当の計算
- 勤務態度、運転、管理、その他手当の適用判定と金額計算
- 寮費など可変控除の基準額計算
- 従業員属性、勤怠、契約、マスター値による適用判定

Ruleは原則として入力Factから金額または判定結果を返す。Rule自身が残高テーブルを直接更新しない。

### 7.2 Ruleで行わないもの

- 日報、残高、取引履歴の登録・更新・削除
- 貯金残高の加算
- 借入金残高の減算
- 法定預り残高の更新
- 月次返金取引の確定
- 月次締めVersion管理
- historyTable／outputTableへの保存
- S3帳票保存

これらはTransactionを伴う業務サービス、月次締めストアドおよび帳票基盤で行う。

### 7.3 処理構成

```text
日報入力
  -> Ruleで支給・手当・控除額を計算
  -> 利用者が確認・必要項目を手入力
  -> 日報と明細を確定保存
  -> 残高サービスが差分を取引履歴へ反映

月次締め
  -> 最新Viewで期間集計
  -> 法定預り返金額を決定
  -> historyTableへ締めVersion付きで保存
  -> 返金取引を確定
  -> outputTable
  -> 月次給与明細PDF
  -> S3保存
```

## 8. マスター方針

### 8.1 新規登録不要

次は既存の専用カラムまたは既存マスターを使用するため、新しい手当・控除マスター行を追加しない。

- 基本給相当
- 早出残業手当
- 深夜手当
- 休日手当
- 貯金（`SAVINGS`登録済み）
- 借入金返済（`LOAN_REPAYMENT`登録済み）
- 法定預り金（`LEGAL_DEPOSIT`登録済み）

### 8.2 設定変更が必要

- 勤務態度手当を日次・月次表示にする。
- 管理手当を日次・月次表示にする。
- 法定預り金を日次手入力・残高追跡対象にする。
- 日報給与Ruleと`daily_pay_rule_setting`の有効設定を作成する。

### 8.3 控除マスターの必須構成

空DB、ローカル、Testcontainers、AWSで次の10コードを必ず利用可能にする。

- `INCOME_TAX`
- `RESIDENT_TAX`
- `HEALTH_INSURANCE`
- `CHILD_SUPPORT`
- `WELFARE_PENSION`
- `EMPLOYMENT_INSURANCE`
- `LEGAL_DEPOSIT`
- `DORMITORY_FEE`
- `MOBILE_RENTAL`
- `WIFI_FEE`

`LEGAL_DEPOSIT`は`MANUAL`・日次手入力、`WIFI_FEE`は月次の確定控除取引として扱う。
前払い・貯金・借入返済は専用基盤を正本とし、旧控除マスター行が存在する場合も
日報へ二重表示せず月次表示用メタデータとして維持する。

## 9. 履歴と正本

- 日報は日次計算結果の正本とする。
- 貯金、貸付、法定預りは取引履歴を残高の正本とする。
- 月次給与明細は締めVersion付きhistoryTableを正本とする。
- outputTableは帳票生成用とし、確定履歴の正本にしない。
- 再締めは最新Viewから新Versionを作成し、旧Versionを上書きしない。

## 10. 必須テスト

- 月給者の通常、早出残業、深夜、休日金額をRuleで計算できる。
- 日報作成、修正、削除で貯金・借入残高の差分が一致する。
- 返済額が借入残高を超える場合は保存を拒否する。
- 法定預り額を日報から手入力できる。
- 法定預り額の日報修正・削除で残高が一致する。
- 月次締めで未返金法定預り残高が全額返金される。
- 再締めで法定預り返金が二重計上されない。
- 過去月再締めが次期間の法定預り残高へ影響しない。
- 日次支払済み金額だけが月次前払いへ集計される。
- 日次給与明細に「前払い」という項目が表示されない。
- 月次給与明細に貯金額・残高、返済額・借入残高を保存できる。

## 11. V1実装状況

2026-08-12時点で、次の基盤実装を行った。

### 11.1 Rule・日報

- 基本給相当、早出残業、深夜、休日金額は既存の`DailyPayComponentCalculationService`と`daily_pay_rule_setting`を使用する。
- 勤務態度手当と管理手当を日次表示対象に変更した。
- 法定預り金は`LEGAL_DEPOSIT`の可変・日次手入力項目とした。
- Ruleは金額計算と適用判定までとし、残高更新は行わない。

### 11.2 法定預り返金

- 日次預り額の正本は`daily_report_deductions`の`LEGAL_DEPOSIT`とする。
- 月次返金履歴は`employee_legal_deposit_refund`へ締めVersion付きで保存する。
- 再締め時は同じ月次締めの旧返金を`SUPERSEDED`にし、新Versionの`ACTIVE`返金を作成する。
- 過去月の再締めでは、対象期間終了後の預り・返金を計算対象に含めない。
- 月次明細では返金を負のその他控除として固定し、差引支給額へ加算する。

### 11.3 帳票スナップショット

- 日次給与明細に法定預り残高、借入金残高、貯金残高を追加した。
- 月次給与明細に法定預り返金額、借入金残高、貯金残高を追加した。
- 月次の各残高と返金額は`monthly_pay_slip_history`と`monthly_pay_slip_render_output`に保存し、後日の残高変更で過去明細を変更しない。

### 11.4 DB適用資産

| 資産 | 内容 |
|---|---|
| `sql/daily_report/legal_deposit_refund_foundation_v1.sql` | 返金履歴テーブル、法定預り残高View、Fuyo用表示設定 |
| `sql/system/report/pay_slip/monthly_pay_slip_view_foundation_v1.sql` | 月次返金・借入・貯金残高の取得 |
| `sql/system/report/pay_slip/monthly_pay_slip_snapshot_foundation_v1.sql` | 締めVersionごとの残高・返金スナップショット |
| `sql/system/report/pay_slip/daily_pay_slip_view_foundation_v1.sql` | 日次明細の残高取得 |

## 12. 割増賃金計算仕様と実装監査

### 12.1 参照資料

- 参照資料：東京労働局「しっかりマスター 労働基準法 割増賃金編」
- 受領ファイル：`000501860.pdf`
- 監査日：2026-08-12

本節はV1の給与計算Ruleを作成・検証する際の基準とする。法改正、就業規則、雇用契約および会社カレンダーに変更がある場合は、期間付きマスターとRuleの適用期間を更新する。

### 12.2 計算要件

| 区分 | V1で扱う法定基準 |
|---|---|
| 法定時間外労働 | 1日8時間または週40時間を超えた時間に25%以上の割増 |
| 月60時間超の法定時間外労働 | 60時間を超えた部分に50%以上の割増 |
| 法定休日労働 | 35%以上の割増 |
| 深夜労働 | 22:00から翌5:00までの時間に25%以上の割増 |
| 法定時間外かつ深夜 | 通常賃金に時間外25%以上と深夜25%以上を加算 |
| 法定休日かつ深夜 | 通常賃金に休日35%以上と深夜25%以上を加算 |
| 月給者の基礎時給 | 割増賃金算定基礎額を1年間における1か月平均所定労働時間数で除算 |

割増賃金算定基礎額から除外できる賃金は名称だけで判断しない。家族手当、通勤手当、別居手当、子女教育手当、住宅手当、臨時賃金および1か月を超える期間ごとに支払う賃金は、実際の支給条件が法令上の除外要件を満たす場合に限って除外する。

### 12.4 Fuyo確定設定

| 設定 | V1仕様 |
|---|---|
| 週の起算 | 月曜日 |
| 通常勤務候補 | 月曜日から金曜日 |
| 休日候補 | 土曜日、日曜日、祝日 |
| 休日手当の最終判定 | 日報の「休日手当対象」で利用者が決定する。土日は新規入力時の初期候補とする |
| 金額端数 | 給与構成額ごとに1円単位、四捨五入 |
| 時間端数 | 開始・終了・休憩を分単位で計算し、時間換算時に小数第2位へ四捨五入する。整数単位への切捨ては行わない |
| 月給者の算定基礎 | V1の既存固定給与では基本給を使用。固定手当を追加する場合は、法令上の除外7項目だけを除外できる期間付き給与構成へ拡張する |

### 12.5 実装方針

1. 法定初期率はRuleパラメータとして管理し、率をサービスへ固定したRuleだけにしない。
2. 休日判定は日報へスナップショット保存し、過去日報を会社カレンダー変更だけで変化させない。
3. 月曜起算の週40時間と暦月60時間を、対象日より前の日報から再計算する。
4. 深夜時間は通常・時間外・休日時間と重複する加算時間として保持する。
5. 月次締めでは日報へ保存済みの給与構成額を集計し、締めVersionへ固定する。
6. 将来、固定月額手当が追加された時点で、割増賃金算定基礎の算入・除外を期間付き給与構成マスターへ切り出す。
7. TestcontainersでRule初期資産の再適用、法定境界、複合割増、再締めを継続検証する。

## 13. 日払い対象と支払サイクル

Fuyoでは全員が月給者であっても、従業員によっては日次支給を前払いとして行う。したがって「給与形態」と「支払サイクル」は別概念として扱う。

| 項目 | 役割 |
|---|---|
| 給与形態 | 月給・週給・日給・時給の賃金計算基礎 |
| 支払サイクル | 計算済み賃金を日払い・週払い・月払いのどの運用で支給するか |

日次支払候補は`支払サイクル=日払い`の従業員だけを対象とする。日次に実際に渡した金額を`daily_payments`へ`PAID`で保存し、月次給与明細では締日までの実支払額を「前払い」として控除する。旧「日払い対象」チェックは使用しない。
