# システムカレンダードメイン V1

## 1. 目的

休日を個別の業務設定から分離し、複数の業務ドメインが同じ基盤を利用できるようにする。

システムカレンダーは次の4種類を同一構造で管理する。

| 種別 | 用途 | V1の編集可否 |
| --- | --- | --- |
| 国民の祝日 | 官公庁・金融機関で共通利用する祝日 | 外部データ取込から更新 |
| 官公庁休日 | 行政手続・官公庁営業日の判定 | 参照のみ |
| 金融機関休日 | 給与・請求などの支払日補正 | 参照のみ |
| 会社休日 | 勤務日・社内業務日の判定 | システム管理者が編集可能 |

休日の管理画面はシステムメニュー配下に置き、業務管理メニューから独立させる。

## 2. データとAPI

- 日付別設定: `system_calendar_holiday`
- 曜日ルール: `system_calendar_weekday_rule`
- カレンダー参照設定: `system_calendar_reference`
- 休日API: `/api/system/calendars/holidays`
- ルールAPI: `/api/system/calendars/policy`
- 権限: `SYS_ADMIN`
- テナント境界: `tenant_id`
- 一意条件: テナント・カレンダー種別・日付

旧 `business_holiday` のデータは初期SQLで会社休日へ移行する。旧テーブルは既存環境との互換性のため直ちには削除しない。

V1の会社休日は、従来仕様を維持するため各年の8月13日から15日を「お盆休み」として補完する。画面で無効化された休日は自動で再有効化しない。

会社休日では次を設定できる。

- 定休日の曜日（初期値は日曜日。土曜日は通常日）
- 官公庁休日・金融機関休日を基準にするか
- 個別の休日（`CLOSED`）
- 定休日や参照先の休日を例外的に営業日にする日（`OPEN`）

同一日の会社個別設定は、曜日ルールと参照先カレンダーより優先する。

## 3. 共通カレンダーの生成規則

| 種別 | 固定規則 | 外部データ |
| --- | --- | --- |
| 国民の祝日 | なし | 内閣府の国民の祝日・休日CSV |
| 官公庁休日 | 土日、12月29日〜1月3日 | 国民の祝日カレンダーを参照 |
| 金融機関休日 | 土日、12月31日〜1月3日 | 国民の祝日カレンダーを参照 |

国民の祝日は、内閣府公式CSVをダウンロードし、外部データ取込の `IMPORT_NATIONAL_HOLIDAY` へアップロードして取り込む。取込前にPythonスクリプトで文字コード・日付・列名を正規化する。

- 公式ページ: `https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html`
- CSV: `https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv`
- 変換スクリプト: `convert_national_holidays_v2.py`
  - CP932 / Shift_JIS / UTF-8（BOM付き含む）を自動判定する。
  - 保存済みの旧版スクリプトを上書きせず、安全に更新できるようバージョン付きファイル名で管理する。
- 保存先カレンダー: `NATIONAL_HOLIDAY`

官公庁休日と金融機関休日は国民の祝日カレンダーを共通参照する。官公庁固有の12月29日・30日は金融機関休日へ継承しない。

## 4. 利用側の方針

休日判定は、利用側が次の2点を明示して組み立てる。

1. 参照するカレンダー種別
2. 前倒し・後ろ倒し方向

日報の日付初期値では次の方針を使用する。

| 対象 | 参照カレンダー | 曜日 | 補正方向 |
| --- | --- | --- | --- |
| 勤務日 | 会社休日 | 会社休日ルール | 前の営業日 |
| 日払い・週払い支払日 | 会社休日・金融機関休日 | 各カレンダーのルール | 後ろ倒し |
| 月払い支払日 | 会社休日・金融機関休日 | 各カレンダーのルール | 前倒し |

業務ごとのサービスが休日テーブルを直接参照することは禁止し、`CalendarQueryService` または `CalendarAdjustmentService` を利用する。

画面上の日付一覧は `YYYY年M月D日` 形式で表示し、APIとDBではISO形式（`YYYY-MM-DD`）を維持する。

## 5. 今後の拡張

- 各カレンダーを利用する業務を段階的に移行する。
- 画面操作から日報初期日付までを確認するE2Eを追加する。
- 旧 `business_holiday` への参照がなくなったことを確認後、互換テーブルと旧SQLを廃止する。

帳票管理、帳票バックアップ、サポートリンクは本対応に含めない。既存機能との責務・データ移行を確認したうえで、別のリファクタリング単位として扱う。
