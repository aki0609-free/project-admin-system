# システムカレンダードメイン V1

## 1. 目的

休日を個別の業務設定から分離し、複数の業務ドメインが同じ基盤を利用できるようにする。

システムカレンダーは次の3種類を同一構造で管理する。

| 種別 | 用途 | V1の編集可否 |
| --- | --- | --- |
| 官公庁休日 | 行政手続・官公庁営業日の判定 | 参照のみ |
| 金融機関休日 | 給与・請求などの支払日補正 | 参照のみ |
| 会社休日 | 勤務日・社内業務日の判定 | システム管理者が編集可能 |

休日の管理画面はシステムメニュー配下に置き、業務管理メニューから独立させる。

## 2. データとAPI

- テーブル: `system_calendar_holiday`
- API: `/api/system/calendars/holidays`
- 権限: `SYS_ADMIN`
- テナント境界: `tenant_id`
- 一意条件: テナント・カレンダー種別・日付

旧 `business_holiday` のデータは初期SQLで会社休日へ移行する。旧テーブルは既存環境との互換性のため直ちには削除しない。

V1の会社休日は、従来仕様を維持するため各年の8月13日から15日を「お盆休み」として補完する。画面で無効化された休日は自動で再有効化しない。

## 3. 利用側の方針

休日判定は、利用側が次の2点を明示して組み立てる。

1. 参照するカレンダー種別
2. 固定で閉じる曜日と、前倒し・後ろ倒し方向

日報の日付初期値では次の方針を使用する。

| 対象 | 参照カレンダー | 曜日 | 補正方向 |
| --- | --- | --- | --- |
| 勤務日 | 会社休日 | 日曜日 | 前の営業日 |
| 日払い・週払い支払日 | 会社休日・金融機関休日 | 日曜日 | 後ろ倒し |
| 月払い支払日 | 会社休日・金融機関休日 | 土曜日・日曜日 | 前倒し |

業務ごとのサービスが休日テーブルを直接参照することは禁止し、`CalendarQueryService` または `CalendarAdjustmentService` を利用する。

## 4. 今後の拡張

- 官公庁休日と金融機関休日の公式データ供給元・更新手順を追加する。
- 各カレンダーを利用する業務を段階的に移行する。
- 画面操作から日報初期日付までを確認するE2Eを追加する。
- 旧 `business_holiday` への参照がなくなったことを確認後、互換テーブルと旧SQLを廃止する。

帳票管理、帳票バックアップ、サポートリンクは本対応に含めない。既存機能との責務・データ移行を確認したうえで、別のリファクタリング単位として扱う。
