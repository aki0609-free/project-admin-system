# メール宛先解決方針 V1

## 1. 目的

ProjectAdminSystem V1における、帳票メールと任意の一斉メールの宛先管理方針を定義する。

## 2. V1確定方針

従業員テーブルおよび顧客担当者テーブルから、メール宛先グループを自動生成・自動同期する機能は追加しない。

DB Triggerによる `mail_recipient` への自動登録も行わない。

理由は次のとおり。

- 個人帳票では、対象者以外への誤送信を防ぐ必要がある
- メールアドレス変更、退職、担当解除、論理削除との同期管理が複雑になる
- 帳票生成時点の宛先は、View／ストアドの確定データとして保持できる
- 任意の一斉送信先は、利用者が明示的に管理する方が安全である

## 3. 宛先の決定方法

### 3.1 従業員向け個人帳票

対象例：

- 日次給与明細
- 月次給与明細

View／ストアドが従業員マスターのメールアドレスを取得し、帳票出力データの `recipient_email` に保存する。

送信処理は、帳票出力時点で保存された `recipient_email` を使用する。

宛先グループによる一斉送信は使用しない。

### 3.2 顧客向け帳票

対象例：

- 請求書
- 顧客別の月次帳票

顧客担当者の次の設定をView／ストアドから参照する。

- `invoice_to_flag = true`：TO宛先
- `invoice_cc_flag = true`：CC宛先

帳票生成・締め処理時点の宛先を出力データまたはメールキューへ保存する。

### 3.3 任意の一斉送信

お知らせや任意の連絡で使用する宛先グループは、メール管理画面から利用者が手動登録する。

既存の次の基盤を使用する。

- `mail_recipient_group`
- `mail_recipient`
- `recipient_group_key`

## 4. エラー処理

- 必須のメールアドレスが未登録の場合、その宛先だけを失敗として記録する
- 他の宛先または他の従業員の処理は継続する
- 失敗理由を帳票出力ファイルまたはメールキューの結果へ記録する
- 空文字および不正形式のメールアドレスは送信対象にしない

## 5. 履歴の考え方

メール送信履歴では、マスターの現在値ではなく送信時に使用した実際の宛先を保持する。

送信後に従業員または顧客担当者のメールアドレスが変更されても、過去の送信履歴は変更しない。

## 6. V2候補

必要性が確認された場合に、次の機能を検討する。

- 従業員／顧客担当者を検索して宛先グループへ追加する選択画面
- 動的宛先グループ
- 自動グループの対象者プレビュー
- メール未登録者一覧

V2で実装する場合も、Triggerで宛先を複製する方式より、送信時に最新データを解決するResolver方式を優先する。

## 7. 対象外

V1では次を実装しない。

- 従業員登録時の `mail_recipient` 自動作成
- 顧客担当者登録時の `mail_recipient` 自動作成
- メールアドレス更新時の自動同期Trigger
- 退職・担当解除時の宛先グループ自動削除

## 8. 実行基盤と環境差異

- メールテンプレート、宛先グループ、送信キュー、テスト送信の管理APIは`SYS_ADMIN`または`ADMIN`に限定する
- PDF Viewerからの送信APIはログイン済み利用者に許可し、画面側の帳票閲覧権限を維持する
- LocalはMailpitを使用し、SMTPを外部へ送信せず`http://localhost:8025`で受信内容を確認する
- AWSはSESを使用する
- 添付ファイルはキューに保存した`storageType`と`fileKey`の組み合わせで取得する
- テスト送信画面でも`LOCAL`と`S3`を明示的に選択し、AWS上の添付をLocalとして誤解決しない
- `sentCount=0`または`failedCount>0`の結果は、画面上で成功として扱わない

## 9. 動作確認

- メールドメインの単体テスト：成功
- LocalアプリからMailpitへのテスト送信：成功
- Local保存のPDFを添付したMailpit送信：成功
- Mailpit受信データの件名、宛先、PDF添付名の確認：成功
