## 1. 顧客別請求単価の適用期間

### 要望

- 適用開始日に過去日を入力しても、消去されず保存できるようにする。
- 適用終了日を単価改定の境界として正しく利用する。
- 無効化した単価が以後の日報入力候補へ出ないことを確認する。

### 現行契約

- バックエンドは過去の適用開始日を禁止していない。
- 適用終了日はその日を含む。
- 同一の現場・職種・現場役職について適用期間の重複は保存不可。
- 日報入力では、有効かつ勤務日が適用期間内の単価だけを候補にする。

### 修正方針

1. V1画面で過去日入力から保存までを再現する。
2. 共通テーブルの日付Editor、日付文字列変換、行のdirty判定を確認する。
3. 意図しない当日以前の入力制限だけを除去する。
4. `YYYY-MM-DD`、終了日≧開始日、期間重複禁止は維持する。
5. 過去開始日、月末終了・翌月初開始、無効化を自動テストへ追加する。

### 単価改定の登録例

- 旧単価: 適用終了日 `2026-11-30`
- 新単価: 適用開始日 `2026-12-01`

新規・更新する日報は勤務日に該当する単価を使用する。保存済み日報へマスター変更を遡及適用する場合は、別途再保存・再計算の運用が必要。

## 2. 現場までの距離

### 要望

- 会社からの距離を小数第1位まで入力・保存・表示できるようにする。

### 現状

- フロントは整数のみ許可している。
- 顧客現場、現場配置・配車の距離がJava `Integer`、DB `INT` である。

### 修正方針

1. 顧客現場と配置時スナップショットの距離を `DECIMAL(...,1)` / `BigDecimal` に統一する。
2. API DTO、Entity、Mapperを小数対応する。
3. 入力欄を `step=0.1`、0以上、小数第1位までに変更する。
4. 表示を `22.5km` の形式にする。
5. 現場マスターから配置・日報へ小数を引き継いでも欠落・切捨てがないことをテストする。

## 3. 請求金額の1円単位切り上げ

### 要望

- 請求金額に1円未満が発生した場合、1円単位で切り上げる。

### 現状

- 請求View・締め処理の主要計算は `ROUND(..., 0)` を使っている。
- 一部のJavaプレビュー計算も `HALF_UP` を使っている。

### 推奨する計算契約

- 通常、残業、深夜、休日、距離請求の各明細金額を計算後、各明細を1円単位で切り上げてから合算する。
- 最新HTMLプレビュー、月次請求View、顧客締め履歴、請求書で同じ結果にする。
- 消費税の端数処理は今回の要望と分離し、既存仕様を変更しない。
- 手入力のその他金額は入力済み金額をそのまま扱う。

### テスト例

- `100.00` → `100円`
- `100.01` → `101円`
- 複数明細を合計した場合も、プレビュー・締め・帳票が一致すること

## 実装順序

1. 過去適用開始日の再現テストと修正
2. 距離のDB・API・画面を一括で小数対応
3. 請求丸めの共通契約をV1内で最小実装
4. 日報保存、最新プレビュー、顧客締め、請求書の回帰テスト
5. Local反映と画面確認
