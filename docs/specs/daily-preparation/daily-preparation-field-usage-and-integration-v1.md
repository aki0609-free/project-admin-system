# 翌日準備 入力項目の利用先・システム連携 V1

ドメイン：翌日準備

## 1. 判定区分

| 区分 | 意味 |
|---|---|
| 利用中 | 画面・作業伝票等から実際に参照される |
| Snapshot | 保存時点のマスター値を業務データへ複写する |
| 保存のみ | DBへ保存するが現行の後続機能では参照しない |
| 未連携 | 連携を期待できるが接続処理が存在しない |
| 派生値 | 利用者入力ではなく、画面・DB処理が生成する |

## 2. 親レコード

保存先：`daily_preparations`

| 項目 | DBカラム | 区分 | 現在の利用先・連携 |
|---|---|---|---|
| 対象日 | `target_date` | 利用中 | 画面取得キー、1日1親レコード、作業伝票対象日・曜日、帳票実行パラメーター |
| 状態 | `status` | 保存のみ | 新規時`OPEN`。`COMPLETED`は将来の承認・完了制御用の予約値で、V1の業務判定には使わない |
| 全体備考 | `note` | 利用中 | 画面で1000文字まで編集できるメモ。作業伝票や日報へは出力しない |

## 3. 従業員配置

保存先：`daily_preparation_assignments`

| 画面項目 | DBカラム | 区分 | 現在の利用先・連携 |
|---|---|---|---|
| 従業員 | `employee_id` | 利用中 | 1準備1従業員を保証し、従業員配置の主キーとなる |
| 社員コード | `employee_code` | Snapshot | 保存時に従業員マスターからコピー。画面並び順・作業伝票の従業員順 |
| 従業員名 | `employee_name` | Snapshot | 画面と作業伝票へ表示 |
| 顧客 | `customer_id` | 利用中 | 現場との分類、作業伝票を顧客・現場単位に分ける |
| 顧客名 | `customer_name` | Snapshot | 画面・作業伝票。後のマスター変更で自動更新しない |
| 現場 | `customer_site_id` | 利用中 | 配車行の生成、作業伝票単位、距離・配車との結合キー |
| 現場名 | `site_name` | Snapshot | 画面・作業伝票 |
| 作業内容 | `work_description` | 利用中 | 作業伝票で従業員ごとに表示 |

新規日報では勤務日と従業員が一致する配置を検索し、顧客・現場・作業内容を初期値として反映する。予定を実績へ強制するものではなく、反映後の値は日報画面で変更できる。既存日報は更新しない。

従業員、顧客、現場の名称は保存時にマスターから再取得する。画面から名称文字列を送らず、IDを正本にする。

## 4. 現場配車

保存先：`daily_preparation_dispatches`

| 画面項目 | DBカラム | 区分 | 現在の利用先・連携 |
|---|---|---|---|
| 顧客 | `customer_id` | 利用中 | 配置と配車を顧客・現場で結ぶ |
| 顧客名 | `customer_name` | Snapshot | 画面表示。作業伝票の顧客名は配置側を主に使用 |
| 現場 | `customer_site_id` | 利用中 | 1準備1現場の一意キー、配置との結合 |
| 現場名 | `site_name` | Snapshot | 画面表示 |
| 会社からの距離 | `distance_from_company_km` | Snapshot | 現場マスターからコピーし、作業伝票へ表示 |
| 配車台数 | `vehicle_count` | 利用中 | 作業伝票へ表示。未入力は0 |
| 配車備考 | `note` | 保存のみ | 画面で編集・保存できるが、現行作業伝票View/JRXMLへ渡さない |

## 5. マスター変更との関係

```text
従業員・顧客・現場マスター
  -> 翌日準備保存時にコード・名称・距離をコピー
  -> 翌日準備テーブルを正本として作業伝票を生成
```

保存後に従業員名、顧客名、現場名、距離をマスターで変更しても、既存の翌日準備は自動更新しない。過去の準備内容を保存時点で維持するSnapshot設計である。

## 6. 作業伝票への連携

| 翌日準備データ | 作業伝票output | 備考 |
|---|---|---|
| `target_date` | 対象日・曜日 | 曜日はMySQLの`DAYOFWEEK`から生成 |
| 顧客・現場ID | `slip_key`、帳票グループ | 顧客＋現場＋ページで一意 |
| 顧客名・現場名 | ヘッダー | 配置Snapshotを使用 |
| 社員コード | 並び順 | 帳票にはコードを表示せず並び順だけに使用 |
| 従業員名 | `employee_name_1`〜`10` | 10名ごとに改ページ |
| 作業内容 | `work_description_1`〜`10` | 従業員と同じslotへ出力 |
| 距離 | `distance_from_company_km` | 配車Snapshot |
| 配車台数 | `vehicle_count` | 配車Snapshot |
| 自社情報 | 会社名・電話・FAX | 有効な会社情報マスターから取得 |

作業伝票の`report_master.history_table`は`NULL`である。通常の帳票実行履歴・生成ファイル履歴は共通基盤に残る可能性があるが、帳票固有の確定データ履歴テーブルは持たない構成である。

## 7. 日報との関係

翌日準備は予定、日報は実績という正本の分離を維持しつつ、新規日報の入力補助として連携する。

```text
翌日準備の配置
  -> 勤務日＋従業員で一致する配置を取得
  -> 新規日報の顧客・現場・作業内容へ初期反映
  -X-> 日報の自動作成・自動保存
  -X-> 既存日報の上書き
```

APIは`GET /api/daily-reports/preparation-defaults?workDate=yyyy-MM-dd&employeeId={id}`を使用する。該当配置がない場合は`available=false`を返す。利用者が初期値を編集した後は、非同期再取得で入力を上書きしない。予定と実績を比較する機能はV1にはない。

## 8. 顧客・現場選択時の画面動作

- 顧客変更：現在の現場をクリアする。
- 現場変更：現場の所属顧客を画面側で設定する。
- 配車行：配置に含まれる現場から自動生成する。
- 距離：顧客現場マスターの`distanceFromCompanyKm`を画面表示し、保存時に再Snapshotする。

## 9. 削除・マスター参照

翌日準備から参照される顧客・現場・従業員は、各マスターの削除Guardで参照対象になる。翌日準備自体は子行を論理削除できるが、親レコードの削除画面・APIはない。
