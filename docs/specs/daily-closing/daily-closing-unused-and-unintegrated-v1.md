# 日次管理 未使用・未連携・不整合調査 V1

## 1. `daily_payments`を正本とする現行実装（対応済み）

保存UI/APIを外し、一覧・日次帳票・月次前払い集計を承認済み日報基準へ統一した。テーブル自体は既存環境との互換のため残している。

## 2. 状態が画面から常に`PENDING`（対応済み）

読取専用化により、日次管理画面から状態を保存しない。支払証明は日次給与明細の生成履歴で管理する。

## 3. 更新時の支払サイクル再検証なし（対象外）

日次管理からの登録・更新を廃止したため対象外。照会時に`paymentCycle=DAILY`を明示判定する。

## 4. 一括保存フラグ検証が弱い（対応済み）

一括保存API自体を廃止した。

## 5. `print-summary`の画面利用が確認できない

金種計算APIがあるが、現行日次管理画面の帳票タブは共通Preview/Batchを利用する。Jasper/View側が別集計なら二重ロジックとなるため、利用先を確認して不要なら削除、必要なら帳票Jobの正本へ統一する。

## 6. 承認状態の明示条件（対応済み）

一覧API・日次帳票View・月次前払いViewのすべてで`APPROVED`を明示条件にした。

## 7. 日次締めVersionがない

画面名から締め処理に見えるが、再締め・Version・確定history・ロックはない。V1では「日次支払内容の確認・証明発行」として扱い、月次締めだけをVersion付き確定とする。

## 8. 月次Viewが`daily_payments`を参照（対応済み）

対象締め期間の日報に保存された計算上支給可能額へ変更した。給与計算基準が`MONTHLY`以外でも月次給与明細の対象となる。
