# 日次管理 項目用途・システム連携 V1

## 1. V1の正本

V1では`daily_report`を日次金額の唯一の正本とする。日次管理は次の項目を読取専用で表示する。

| 項目 | 正本 | 利用先 |
|---|---|---|
| 対象日 | `daily_report.payment_date` | 日次一覧・日次帳票 |
| 従業員 | `daily_report.employee_id`→`employee` | 対象者判定・一覧・帳票 |
| 日次前払い額 | `SUM(daily_report.estimated_net_pay_amount)` | 概要・明細・日次給与明細・月次前払い |

`daily_payments`テーブルは既存DBとの互換のため直ちにDROPしないが、V1の日次画面・日次給与明細・月次前払い計算では参照・更新しない。

## 2. 対象者条件

対象者は「給与計算基準が日給か」ではなく、従業員契約の`paymentCycle=DAILY`で判定する。会社が月末精算を行いながら日次前払いをする運用では、給与計算基準と支払サイクルは別概念として扱う。

## 3. 日報との連携

日報側では勤務日と支払日を別に持つ。同じ支払日に複数日の日報があれば、従業員単位で合算する。

```text
日次前払い額 = SUM(APPROVED daily_report.estimated_net_pay_amount)
実際前払い額 = 日次前払い額
```

日次管理では金額や備考を保存しない。訂正は日報で行い、日次給与明細を再発行する。

## 4. 月次との連携

月次Viewは支払サイクルが`DAILY`の従業員について、締め対象期間内に`payment_date`を持つ承認済み日報の`estimated_net_pay_amount`を前払いとして差し引く。給与計算基準（時給・日給・週給・月給）は対象可否に使わない。

## 5. 画面集計

対象人数と日次前払い合計は取得行を画面で合算する。サーバーの`print-summary`は同じ日報由来金額から紙幣・硬貨別の金種を返す。

## 6. 発行履歴

日次給与明細は「その金額を日払いしたことの証明」であり、生成ファイル履歴を残す。訂正時は日報を修正して再発行し、旧ファイルを上書きしない。月次確定は日報の締め期間集計を月次締めVersionへ保存する。
