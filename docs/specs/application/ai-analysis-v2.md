# AI分析 V2導入方針

## 結論

生成AIによる応募・媒体分析はV2へ回します。V1の応募者管理・応募媒体管理は、AIがなくても登録、集計、チャート、採用単価確認が完結する状態をリリース条件とします。

## 現在できているところ

- 応募媒体の集計データ作成
- AIへ渡すリクエスト形式とプロンプト生成
- 分析APIと分析履歴の保存先
- フロントの分析表示領域とAPI呼び出し部品
- AI無効時に実行させない制御

現在はOpenAI向けの実装が残っていますが、フロント側ではAI実行が明示的に無効です。したがってV2でAWS Bedrockへ切り替えても、V1の業務フローを作り直す必要はありません。

## V2での推奨構成

業務機能からBedrock SDKを直接呼ばず、次の境界を設けます。

1. 応募者・媒体機能が、個人情報を必要最小限にした分析入力を作る
2. 共通の `AI分析実行` インターフェースへ渡す
3. Bedrock用アダプターが選択モデルを呼ぶ
4. 構造化レスポンスを検証する
5. モデル、プロンプト版、入力ハッシュ、所要時間、成否、費用見積を履歴へ保存する
6. AIが失敗しても通常の集計・チャートは表示し続ける

この分離により、安価なモデルから開始し、精度不足の場合だけモデルを変更できます。

## V2着手前に決めること

- 分析結果を「参考情報」とするか、業務判断へ利用するか
- 氏名、電話番号、メール等をモデルへ送らない匿名化範囲
- 利用するBedrockモデルとリージョン
- 1回当たりの入力上限、月額上限、タイムアウト、再試行回数
- プロンプトの版管理と評価用の正解例
- 不適切・不正確な回答の表示方法
- 履歴の保存期間と閲覧権限

## V1で残す表示

- 応募数、面接数、採用数、在籍・退職状況
- 媒体別費用、採用数、採用単価
- 月別推移と絞り込み
- 「AI分析はV2予定」であることが分かる無効表示

V1でAIの呼び出しだけを急いで有効にすると、個人情報、費用上限、回答品質、障害時の扱いが未確定のまま本番機能になります。そのため、Bedrock採用自体は妥当ですが、V2として評価・監査・失敗時制御を含めて導入します。
