# HR分析（応募者・応募媒体）V1確認結果

## V1で確認する範囲

- 応募者の登録・参照・更新・削除
- 応募者が既存の応募媒体へ正しく関連付くこと
- 採用状況が `HIRED` の応募者数を、応募媒体の採用数へ反映すること
- 応募媒体の費用 ÷ 採用数を採用単価として再計算すること
- 応募者の媒体変更時に、変更前と変更後の両媒体を再計算すること
- 応募者が存在する応募媒体を誤って削除できないこと

## データ連動

1. 応募者の保存時に、既存の媒体ID、または媒体名と掲載年月から応募媒体を解決します。
2. 応募者は `application_media_id` で媒体と関連付きます。
3. 保存時点の媒体名と年月もスナップショットとして応募者へ保持します。
4. 応募者の登録・更新・削除後に、関連媒体の採用数と採用単価を再計算します。
5. 採用数が0件の場合、採用単価は未設定に戻します。

画面で既存応募者を編集する場合は、レスポンスで受け取った媒体IDを保持して更新APIへ返します。これにより、媒体名や年月から別レコードへ誤って結び直されることを防ぎます。新規入力で媒体IDがない場合は、媒体名と問い合わせ年月で既存媒体を検索し、なければ媒体を新規作成します。

## 2026年9月13日の確認結果

- サービス層テスト: 登録連動、媒体変更、削除連動、採用単価、参照中媒体の削除拒否を確認済み
- フロント単体テスト: 既存媒体IDを更新リクエストへ保持することを確認済み
- Local実DB: 媒体登録 → 応募者登録 → 応募者詳細 → 採用数・採用単価 → 応募者削除 → 採用数0件、まで確認済み
- 実DB確認時に、旧列 `applicants.dynamic_fields` が必須のため応募者登録が500になる問題を検出。現行データを壊さずNULL許可へ変更する互換SQLを追加済み

## V1とV2の境界

V1は、登録データを基にした表・グラフ・決定的な集計までを提供します。生成AIによる解説や提案はV2とし、V1では実行ボタンを無効のままにします。詳細は [AI分析 V2導入方針](./ai-analysis-v2.md) を参照してください。
